# Модель защиты

## Разговор

LiveKit использует WebRTC. Для приватных комнат включены `encryption`, внешний
провайдер ключей и отдельный worker на клиенте. Ключ сайта создаётся Web Crypto;
для приглашений из Telegram его создаёт бот через `secrets.token_urlsafe(32)`.
Приглашение содержит ключ во фрагменте URL. Это общий секрет комнаты, а не
идентификация каждого получателя. Участники могут переслать приглашение.

Выдача JWT приватной комнаты требует серверной проверки производного значения
`SHA-256("VoiceRooms admission v1:" + key)`. В базе хранится SHA-256 этого значения.
Код комнаты без ключа недостаточен для входа. Проверочное значение не является
ключом расшифровки медиапотока. Оно передаётся в теле HTTPS-запроса, не в URL.
При первом обновлении закрываются старые приватные комнаты без проверочного
значения. Новые приватные комнаты сохраняются при обычном перезапуске.

Файлы шифруются на клиенте AES-256-GCM со случайным 96-битным IV. Сервер хранит
только двоичный шифротекст под случайным именем. Исходное имя передаётся в
зашифрованном чате. Загрузка и получение требуют сессии комнаты; срок доступа —
5 минут, фоновое удаление запускается раз в минуту.

Публичные комнаты используют транспортное шифрование. Имена, роли, состав
участников и сигнализация не являются сквозно зашифрованными.

## Сессии и управление

Гостевые сессии подписаны HMAC и имеют срок действия. Идентификатор гостя
отрицательный; в медиасервер передаётся отдельный HMAC-псевдоним для каждой
комнаты. Telegram initData проверяется по подписи, уникальности полей и возрасту.
Телефон, контакты и фотографии не запрашиваются.

Права создателя проверяет API. Клиент не получает `roomAdmin` в JWT. Управление
владельцем сервиса требует подтверждённой Telegram-сессии либо одноразового
кода: 5 минут на обмен, однократное использование, подписанная сессия на сутки.
Идентификатор Telegram сам по себе не является ключом доступа.

Участие владельца обозначается подписанной сервером ролью. Подключение не
скрывается. Для приватного медиапотока ключ нужен владельцу наравне с другими.
Разрешение микрофона не включает его без действия самого участника.

Удаление отключает участника и запрещает выдачу нового токена его сессии.
Подписанные события LiveKit повторно удаляют запрещённую сессию при попытке
использовать ранее выданный JWT. Поэтому webhook из `livekit.yaml` является
обязательной частью развёртывания. Новый анонимный браузер с другим сеансом
нельзя надёжно связать с прежним человеком; против целевого преследования
нужно закрыть комнату и отправить новое приглашение.

## Эксплуатация

База и API не публикуются в Интернет напрямую. WebSocket идёт через HTTPS
обратного прокси, медиапорты ограничены диапазоном. Секреты не попадают в образы
или исходники. Загрузки, база и системные журналы требуют собственных резервных
копий и контроля доступа. Не добавляйте рекламную аналитику или сторонние
скрипты на страницу приватного разговора без пересмотра модели защиты.

Это прикладная проверка проекта, а не независимый криптографический аудит.
