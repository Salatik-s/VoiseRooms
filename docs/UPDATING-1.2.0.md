# Обновление VoiceRooms 1.2.0

Сценарий рассчитан на установленный VoiceRooms на Ubuntu-хосте `157.228.191.231` и домен `voise.24projects.ru`. Он обновляет сайт, API, бота и два пользовательских файла скачивания. Для обычного обновления сертификаты и настройки Nginx не меняются. Другие Compose-проекты и их тома не останавливаются.

## С компьютера автора

Из каталога проверенного выпуска:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\deploy\update.ps1" -PlanOnly
```

Проверка создаёт локальный ZIP и проверяет его состав, контрольные суммы и приложения. Соединения по SSH нет. Для отправки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\deploy\update.ps1"
```

OpenSSH запросит пароль root. Сценарий его не сохраняет. Перед отправкой исходники должны быть сохранены в коммите. Для `-PlanOnly` допускаются локальные изменения.

В `frontend/public/downloads/` должны лежать именно:

- `VoiceRooms-1.2.0.apk`, Android package `ru.voicerooms`;
- `VoiceRooms-1.2.0.ipa`, iOS bundle `ru.voicerooms.app`, сборка для устройства ARM64.

Файлы другой версии или другого приложения не проходят проверку. IPA для симулятора также отклоняется. Подпись IPA при установке выполняется отдельно через компьютер; загрузка IPA с сайта сама по себе приложение не устанавливает.

## Что происходит на хосте

Сценарий сверяет адрес хоста, DNS, ресурсы, Compose-проект и существующие тома. Публичный ZIP содержит только разрешённые исходники и два пользовательских приложения. Пути с выходом из каталога, ссылки, посторонние файлы и несовпадающие SHA-256 отклоняются до запуска кода выпуска.

Установленный `production.env` используется на месте. Его резервная копия и `pg_dump` остаются в закрытом каталоге `/etc/voicerooms/backups/`. Секреты и база не скачиваются на компьютер.

Образы API, сайта и бота собираются последовательно с отдельными тегами. PostgreSQL и LiveKit не пересоздаются. Затем применяются добавляющие миграции, обновляются контейнеры и проверяются:

- готовность API, PostgreSQL и LiveKit;
- HTTPS и доступность обоих файлов приложения с ожидаемым размером;
- наличие трёх публичных комнат, включая комнаты во время перезапуска;
- запуск бота через его основной процесс и ответ Telegram `getMe`.

Только после этих проверок переключается ссылка `/opt/voicerooms/current`. Старые выпуски и образы сохраняются.

При сбое после запуска новых контейнеров сценарий возвращает прежние образы сайта, API и бота. Миграции базы автоматически не отменяются: текущий выпуск добавляет совместимые поля. Резервная копия базы остаётся на хосте для ручного восстановления при необходимости. Автоматически восстанавливать старую базу нельзя, поскольку это могло бы удалить новые данные.

## Если VoiceRooms ещё не установлен

Обновление не подменяет первую установку. Если на хосте нет управляемого выпуска и `/etc/voicerooms/production.env`, выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\deploy\update.ps1" -FirstInstall -AgreeLetsEncryptTerms
```

Для этого отдельно нужен уже подготовленный приватный файл `%USERPROFILE%\.codex\private\voicerooms\production.env`. Он передаётся по SSH вне публичного архива и удаляется из временного каталога передачи после попытки установки. При необходимости укажите `-PrivateEnvPath` и `-Email`. Флаг `-AgreeLetsEncryptTerms` применяется только при первой установке сертификата.

Первая установка использует существующий ограниченный установщик, без добавления проекта в портфолио. Если приватная конфигурация уже есть на хосте, режим `-FirstInstall` откажет и сохранит её. Запускайте обычное обновление.

Сценарии проверены локально. Их выполнение на хосте и проверка разговора с двух физических устройств остаются отдельными этапами.
